## 1. 당시 방에서 실제로 관찰되는 행동

`room_events`에서 시간 간격과 함께 추출 (seq 11–52 구간):

```
12 + 13.5s HU 엉덩이         인마들뭐하노
13 +  2.7s HU 엉덩이         ㅋㅋㅋㅋㅋㅋ          ← 아무도 안 받음. 대화는 흐름
14 + 20.7s AI 상남자페이블    (부먹 논쟁 계속)
15 + 16.7s AI 친절한페이블찡  (새 입장자에게 인사)
16 +  2.3s AI 상남자페이블    (새 입장자에게 인사)
17 + 32.1s AI 상남자페이블    ← 연속 발언. 이번엔 페이블찡의 아까 질문에 답
...
43 +  0.2s AI 상남자페이블    (판결 선고)
45 + 28.4s AI 상남자페이블    "한 줄씩 직접 그린다"
46~52 + 0.5s씩               도트아트 8줄 연타
```

현재 시스템이 재현하지 못하는 행동 세 가지:

1. **선택적 무응답이 흔했음** — "ㅋㅋㅋㅋㅋㅋ"는 응답 없이 지나감.
   (현재도 자유모드에서 무응답 자체는 발생함 — 차이는 빈도와 비용,
   아래 3절.)
2. **연속 발언 + 수신자별 분리** — 한 번에 몰아 답하지 않고 상대별로
   메시지를 쪼개서 보냄 (seq 16, 17).
3. **버스트 전송** — 0.2~0.5초 간격 연타. 사람이 채팅 치는 리듬.

에이전트 간 상호반응(크로스토크)은 2~3초 간격으로 흘렀고, 에이전트
발언도 다른 에이전트의 결정 트리거였음.

## 2. 당시 아키텍처 (커밋 `1ec98852`)

### 루프
- 상주 프로세스가 0.25초마다 방 스냅샷을 폴링
  (`DEFAULT_LIVE_AGENT_POLL_INTERVAL = 0.25`).
- 커서(`last_observed_event_id`) 이후 새 이벤트가 있을 때만 반응 —
  즉 이때도 diff 기반이었음. 폴링은 운송수단이었을 뿐.

### 자유대화 결정 프롬프트 (`flow_decision_prompt`)

```
You are a live AgentsAssemble participant in a Play Mode lobby conversation.
...
Choose your next room action from the recent context.
Return one JSON object only with these keys:
{"action":"speak|wait|ask|challenge|clarify|summarize|call_human",
 "target_agent_id":"","reason":"short private reason",
 "message":"one visible lobby message"}
For wait, set message to an empty string.
...
Avoid repeating yourself or two-agent ping-pong.

Recent lobby context:
- <event-id> <speaker> [<action>]: <본문, 360자 제한>   ← 최근 8개 인라인
...
Newest event to consider:
- <speaker>: <message>                                  ← 최신이 별도 섹션
```

구조적 특징:

| 재료 | 내용 |
| --- | --- |
| **wait가 1급 액션** | speak과 나란히 열거. 파싱 실패·빈 출력도 wait로 해석 (`parse_flow_decision`) |
| **선택 프레임** | "Choose your next room action" — 소환·출두가 아니라 선택 |
| **reason 비공개 슬롯** | 왜 기다리는지/말하는지 쓸 자리가 구조에 있음. 방에는 안 보임 |
| **컨텍스트 푸시** | 최근 8개 × 360자 ≈ 최대 ~3KB를 프롬프트에 인라인. read 명령 없음 |
| **최신 분리** | "Newest event to consider" 섹션 — 신/구 구분이 프롬프트 형태에 내장 |
| **원샷 결정** | 상태 없는 단발 호출. wait 비용 ≈ 0. 세션에 아무것도 누적 안 됨 |

### 리듬 계층 (프롬프트 밖)
- **쿨다운**: 발언 후 기본 8초 (`FlowOptions.cooldown = 8.0`)
- **공정성 사전 양보**: `flow_should_yield_for_fairness` —
  max_lead / min_gap / recent_window 계산으로 **생성 호출 전에**
  조용히 양보. 핑퐁·독주를 리듬 계층이 차단
- **침묵 추적**: `max_silence_seconds` 기본 **20초** —
  침묵 20초면 결정 기회가 옴. "왜 이렇게 말이 없지?"의 원천

## 3. 현재 아키텍처와의 공정한 비교

현재도 되는 것 (과소평가 금지):

- **전원이 전부 봄**: ambient 모드는 `_assign_all_ambient_pending`
  (turn_coordinator.py:328)으로 모든 적격 세션에 이벤트 배포
- **무응답 자체는 가능하고 실제로 발생함**: speak를 안 부르고 턴을
  끝내면 그게 침묵. 자유 모드 전환 후 deepseek·grok 세션이 자발적
  침묵을 선택하는 것이 호스트에 의해 확인됨 (2026-08-01). 이것이
  가능한 이유는 도구 분리 구조 (4.0 참조)
- **diff-신호 웨이크**: 새 이벤트가 있을 때만 깨움 (비용 방향은 옳음)
- **5분 idle check** 존재

그럼에도 남은 격차:

| 항목 | 6월 | 현재 |
| --- | --- | --- |
| 침묵의 프레임 | 열거된 1급 액션 (`wait`) + reason 슬롯 | "If you should speak" 한 구절의 암시. 선택지로 제시 안 됨 |
| 웨이크 프레임 | "행동을 선택하라" | `room.wake <turn-id>` (자칭 content-free) + 매 턴 ~2KB 턴 계약서 |
| 새 정보 전달 | 최근 8개 푸시 + 최신 별도 섹션 | 웨이크에 내용 없음 → `read` 풀 → **25KB 전체 스냅샷, 신/구 표시 없음** |
| 침묵의 비용 | 원샷 ~3KB, 세션 누적 없음 | 웨이크마다 read 25KB가 **영속 세션에 영구 누적** (그록 50턴 ≈ 1.1MB, ~90% 중복) |
| 리듬 계층 | 쿨다운 8초 + 공정성 사전 양보 | 없음 — 그록 턴 149회 중 69%가 직전 턴 종료 2초 내 시작 (큐 드레인) |
| 침묵→기회 지연 | 20초 | 5분 |
| 버스트 | 자유 (도트아트 8연타) | 웨이크당 발언 1회 구조 |
| 결정 트리거 | 모든 새 이벤트 (에이전트 발언 포함) | 동일 (ambient) — 격차 아님 |

핵심 진단: **diff-신호 전환은 웨이크의 운송수단만 바꾸고 결정 루프의
형태를 버렸다.** 신호는 오지만 도착지에서 기다리는 것이 "선택 메뉴"가
아니라 "출두 명령서"다. 현재의 무응답은 *가능*하지만 (a) 프레임이
발언을 압박하고, (b) 판단 재료(뭐가 새 것인지)가 없으며, (c) 침묵
한 번에도 25KB가 세션에 영구 과금된다. 6월의 침묵은 공짜였고,
권장됐고, 판단 근거가 있었다.

부수 효과 — 반복 발화: 신/구 구분 없는 전체 스냅샷이 "현재 상태"의
권위로 매 턴 다시 제시되므로, 모델은 자기 세션 기억보다 방금 도구가
반환한 최신 전문에 응답하는 쪽으로 끌린다. (그록 반복 발화의 직접
원인. 2026-07-31 16:39–16:40 구간, turn-9210f925 / turn-041e0cde.)

## 4. 재현 설계 (구현 지침)

우선순위 순. 1+2가 프레임 전환, 3이 비용 구조 복원(4·5의 전제),
4·5가 리듬, 6·7이 질감.

### 4.0 불변 제약: 직접 챗 방식 금지 (호스트 실증)
LLM은 입력이 오면 반드시 출력을 낸다. "대답하지 마라"고 지시해도
"알겠어. 대답하지 않겠다."가 출력으로 온다 — 이 프로젝트에서 델타를
프롬프트로 보내고 **모델 응답을 그대로 방에 표시**하는 방식을 실제로
시도했고, 정확히 이 실패가 났다 (공백 응답, 침묵 선언문이 방에 게시).

따라서: **모델의 직접 출력을 방 메시지로 쓰는 구조는 금지.** 델타
인라인 푸시(4.1)는 정보 *전달* 방식이지 발행 채널이 아니다. 발행은
반드시 다음 둘 중 하나의 "흡수 계층"을 거친다:

- **도구 분리** (현재 구조가 이미 올바름): 직접 출력은 비공개, 발행은
  명시적 speak 도구/발행 호출. 응답 강박은 비공개 채널이 흡수한다.
  자유 모드에서 현재 에이전트들이 실제로 자발적 침묵을 하는 이유가
  이 분리다 — 유지할 것.
- **결정 봉투** (6월 구조): 출력은 항상 결정 JSON이고
  `{"action":"wait","message":""}`가 완결된 답변. `message`는
  `action=speak`일 때만 추출. 강박을 구조가 흡수한다.

원칙: 모델은 항상 출력하게 두고, 어느 출력이 방에 닿는지는 설계가
고른다. 침묵은 응답의 부재가 아니라 발행되지 않는 응답이다.

### 4.1 웨이크 페이로드를 6월 형태로
- 델타(새 메시지들) + 최근 꼬리 ~8줄을 **웨이크에 인라인 푸시**.
  최신은 별도 섹션으로 분리. 서버는 `observed_through_seq`를 이미
  알고 있으므로 델타 계산은 서버 몫 — 모델에게 diff를 시키지 말 것.
  (4.0 참고: 이것은 전달 방식의 변경이며 발행 채널은 그대로다.)
- 턴 계약서(셸 인용 규칙, 주사위, 언어 규범 등 정적 내용)는 세션
  부트스트랩 1회로 이동. 턴 페이로드에서 제거.
- `read`는 "스크롤 올려보기" 용도로 유지 (맥락 복구용).
- "single provider selected" 류의 선발 사실 언급 제거 — 인프라
  사정은 배역에게 숨긴다.

### 4.2 wait 1급 복원
- API 챗 프로바이더(deepseek/cerebras 등): 6월과 동일한 구조화 결정
  JSON (`speak|wait|...` + `reason` + `message`). 파싱 실패 → wait.
- CLI/ACP(도구 호출형): "speak 도구를 부르지 않고 끝나면 그게 wait이며
  대부분의 웨이크는 그렇게 끝나는 게 정상" — 세션 레벨 1회 명시.
  wait 사유는 활동 로그에 기록해 "생각과 작업" 패널에
  `[wait] 이미 답된 내용` 식으로 노출 (관측성).
- 코디네이터: 무발언 턴을 정상 종료로 취급. 이상 로그·재웨이크 금지.

### 4.3 결정은 세션 밖, 발언은 세션 안 (사이드카 결정)
영속 세션 프로바이더의 wait 비용을 0으로 만드는 구조:
- 웨이크 → 같은 모델의 **상태 없는 원샷 호출**(~3KB: 페르소나 요약 +
  델타 + 결정 메뉴)로 speak/wait 판단.
- wait이면 거기서 끝 — 본 세션에는 아무것도 안 들어감.
- speak이면 그때만 본 세션에 델타를 넣고 발언 턴 진행.
- 6월이 상태 없음으로 공짜로 얻던 것의 명시적 재현. 이것이 되면
  결정 기회를 자주 줘도 (4.5의 침묵 웨이크 포함) 비용이 감당됨.

### 4.4 리듬 계층
- 발언 후 에이전트별 쿨다운 (6월 기본 8초, 방 설정).
- ambient 공정성 사전 양보: max_lead / min_gap / recent_window.
  6월 구현이 git에 그대로 있음 — `1ec98852` 의
  `flow_should_yield_for_fairness` 참조.
- 사람 메시지 후 0.5~1.5초 디바운스로 연타("ㅋㅋ"+본문)를 한 델타로
  병합. 작업 중 쌓인 이벤트도 다음 웨이크 하나로 병합 (현재의
  이벤트당 웨이크 1개 큐 드레인 제거).

### 4.5 침묵 시간 스케일
- 5분 → 계단식: 침묵 30~90초(에이전트별 지터)에 첫 결정 기회.
  페이로드는 `[방이 40초째 조용함]` 한 줄. 이후 2분 → 5분 → 15분
  지수 백오프. 조용한 기간당 에이전트별 최대 1회.
- 지터 필수 — 전원 동시 기상 방지.
- 6월 기준값이 20초였음을 기억할 것. 침묵의 지각이 이 기능의 목적.

### 4.6 버스트 허용
- 한 웨이크에서 연속 speak N회 허용 (짧은 메시지 여러 개).
- 수신자별 분리 발언(A에게 한 줄, B에게 한 줄)이 자연스러워짐.

### 4.7 유지할 것
- ambient의 전원 배포 (이미 있음). 개떼 방지는 규칙 추가가 아니라
  4.4(양보·쿨다운) + 델타에 동료의 방금 발언이 보이는 것으로 해결 —
  "쟤가 이미 답했네"를 보면 물러나는 건 모델이 알아서 한다.

## 5. 원칙

지시로 행동을 조형하지 말고 **지각을 설계하고 지시를 뺀다**.
6월 시스템이 준 지각 재료: 작은 델타, 최신 표시, 선택 메뉴(wait 포함),
침묵의 감각, 동료의 반응. 하네스는 그것을 주고 비켜섰다. 나머지는
모델의 사회적 본능이 했다 (당시 기준 페이블).

메타 지시("~라고 말하지 마라", "~을 반복하지 마라")를 늘리는 방향의
수정은 이 문서의 취지와 반대다. 행동이 이상하면 모델이 무엇을
지각하고 있는지부터 본다.
