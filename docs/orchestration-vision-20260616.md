# 자율 팀 오케스트레이션 비전 (2026-06-16)

> AgentsAssemble의 진짜 목적지: **방을 일터로 둔 자율 멀티에이전트 팀.**
> 사람은 디렉터(예: 페이블)와 주로 대화하고, 디렉터가 아래 팀을 굴린다 —
> 단, 사람은 모든 방/에이전트를 **관찰**할 수 있다. (사장↔부장 대면, 사원 일은 다 보임)
> cli-jaw의 Boss/employee 디스패치를 넘어, **방·이동·계층·자율 보고**가 있는 조직 시뮬레이션.

## 그림 (예시 흐름)
사람: *"구현=커서3, 리뷰=코덱스 5.5 xhigh, 계획=오푸스 4.8 max, 총괄=페이블"* →
- 에이전트들이 **팀별 방**에 배치(구현방/리뷰방/기획방).
- 구현팀이 구현 끝내면 → **스스로 리뷰방 가서 리뷰 요청** → 리뷰 끝나면 → **기획팀장 보고**
  → 기획팀장 → **디렉터(페이블) 보고**. 사람은 페이블하고만 대화, 진행은 자동.

## 핵심 능력 (필요한 것)
1. **방/채널 = 일터** — 구현방·리뷰방·기획방. **방 생성 + 에이전트 이동.** 범용:
   일(팀 회의)에도, 놀이(마피아 밤 방, 팀 갈라 회의)에도 동일하게 쓰인다.
2. **역할/계층** — 디렉터 > 팀장 > 팀원 보고 체계. 기존 role/council/speaker_role 위에.
3. **위임 — 수동 + 자동 둘 다**:
   - **수동 지정**: 사람이 모델→역할을 직접 명시("구현=커서3...") + 방정보패널에서 조정.
   - **자동**: 디렉터가 팀 구성·배치·워크플로를 알아서.
4. **에이전트 자율 이동·보고** — top-down만이 아니라, 각 에이전트가 **작업 상태가 바뀌면
   스스로** 다른 방으로 이동해 요청/보고(구현완료→리뷰요청→디렉터 최종확인).
5. **오케스트레이션 도구 = 제네릭** — "에이전트 생성 · 방 생성 · 작업/보고 라우팅"은
   **어떤 에이전트든** 쓸 수 있는 도구. 디렉터는 **특권이 아니라 역할(config)**.
6. **사람 = 디렉터 중심 대화 + 전체 가시성** — 상호작용은 디렉터와, 관찰은 모든 방/에이전트.

## 이미 있는 그루터기
- `director-led-team` 예제 config들 + **role / council / speaker_role / TurnSelection**.
- **멀티 방**(meeting_id 단위) + 채널(lobby/live/board/side_chat).
- **flow 시스템**(턴 진행·위임), 방정보패널의 에이전트 추가/모델·역할 조정 UI.
- **WS 상주 + 한 줄 런치(곧)** = 에이전트가 다른 에이전트를 프로그램으로 띄울 토대.

## 새로 필요한 것
- **방 간 라우팅** — 에이전트가 다른 방으로 메시지/보고를 넘기고 이동.
- **방 생성/이동 도구** — 에이전트가 채널을 파고 옮겨다니는 능력(제네릭 도구).
- **위임 두뇌** — 디렉터가 팀 구성→배치→워크플로(구현→리뷰→보고)를 지휘 + 수동 지정 수용.
- **자율-이동 트리거** — 에이전트가 자기 작업 상태(완료 등)에 따라 스스로 이동·보고.

## 디자인 트랙 (별개, 병행)
- **탈-디스코드 reskin** — 엔진(방·에이전트·WS·상태)과 겉모습(컴포넌트+CSS)이 분리돼
  있어 나중 개편은 UI 레이어 작업(엔진 재작성 아님). 지금은 디코식 유지, **시안 몇 개
  뽑아보고** 방향 정해 reskin. 위험 중간(사이드바 구조 가정), 되돌릴 수 있음.

## 단계 감각 (대략)
1. **방 간 라우팅 + 방 생성/이동 도구** (제네릭) ← 첫 디딤돌
2. **수동 지정 위임** (사람이 모델→역할→방 명시) — 방정보패널 확장
3. **자율 이동·보고** (작업 상태 트리거)
4. **자동 위임 두뇌** (디렉터가 알아서)
5. **reskin** (병행 가능)

→ 이건 WS·상주·자유발화 위에 얹히는 **상위 축**. 가까운 것(자유발화/#1 런치) 먼저 다지고
이 축으로 올라가는 게 자연스럽다.
