# AgentsAssemble 플랫폼 비전 (2026-06-15)

> 출발점은 "디스코드 같은 멀티에이전트 채팅방"이었지만, 목표는
> **"방을 사회 레이어로 둔, 배포 가능한 멀티에이전트 클라이언트/플랫폼"**이다.
> Cursor / opencode / Claude Code 와 같은 급의 클라이언트인데, 차별점은
> **멀티에이전트 + 방(공유 공간) + 로컬·웹 배포 선택**이다.

이 문서는 방향을 못 박는 용도다. 구현 순서·범위는 아래 단계표를 따른다.
**빅뱅 금지** — 한 번에 다 손대지 말고 단계별로, 각 단계는 테스트 + 실서버 검증을 포함한다.

---

## 세 기둥

### 기둥 1 — 배포 모드 선택 (방을 어디에 파느냐)
같은 코드베이스가 세 모드로 동작:
- **순수 로컬**: 나 혼자, 인터넷 0 (SQLite, 터널 없음)
- **로컬 서버 + 외부 초대**: 내 PC가 서버, 터널로 외부 초대 (현재 방식)
- **웹 공개**: 클라우드 control plane, 누구나 접속

목적: **실행은 내 기계, 조종은 어디서든(폰 포함).** "control plane(방·신원·채팅) ↔ execution(에이전트)" 분리가 핵심.

설계 원칙:
- **저장 백엔드 swappable**: 로컬=SQLite(`identity.db`) / 웹=Postgres. `identity_store` 추상화를 백엔드 교체 가능하게 유지.
- **에이전트 2종**: 로컬 CLI 에이전트(내 기계 필요) vs 클라우드 API 에이전트(어디서든). 웹 공개 모드에서 API 에이전트는 100% 동작, CLI 에이전트만 로컬 기계 연결 필요.

### 기둥 2 — 모델 제공 (BYOK + 무료 + 유료)
runner의 provider 추상화 위에 모델 공급 경로를 넓힌다:
- **로컬 오픈모델** (LM Studio Llama/Qwen) — 비용 0, 이미 있음
- **무료 엔드포인트 중개** — NVIDIA `build.nvidia.com`(MiniMax/Nemotron 무료), OpenRouter `:free`. **우리가 대납하지 않음** — 모델사/중개소가 부담, 우리는 중개만. 대가: 한도·속도제한·데이터 학습 가능성(사용자 고지 필요).
- **BYOK** — 사용자가 자기 API 키. 결제는 사용자 몫, 우리 위험 0.
- **유료 구독제 (먼 미래)** — 우리가 모델비 대납 + 구독료 회수. 결제·사용량 측정·마진·법무가 따라오는 **사업 단계**. 사용자/트래픽 생긴 뒤. 단, **사용량 기록 스키마는 0단계에서 자리만 비워둔다**(기존 quota 추적의 연장).

핵심 주의: **무료는 변한다.** 특정 무료 모델에 의존하지 말고 무료 풀을 갈아끼울 수 있는 provider 추상화로 둔다.

### 기둥 3 — 앱급 권한/능력 (채팅방 → 클라이언트)
Claude Code/Cursor/opencode 앱처럼 클라이언트가 에이전트 능력을 제어:
- **웹으로 가능한 것**: 세션 허용 플로우, 권한 건너뛰기 토글, BYOK 키 관리 UI, provider/모델 선택
- **네이티브 앱이 있어야 하는 것**: file access(파일시스템 접근), voice 입력(마이크), OS 권한, 진짜 기기 신원 — 웹 브라우저 보안 천장 너머
- **캐시 히트(prompt caching)**: 권한이 아니라 비용/속도 최적화. 같은 "클라이언트가 provider 호출 관리" 레이어에 두되 성격은 별개.

→ 기둥 3의 절반은 **네이티브 앱을 요구한다.** 앱은 나중이지만 권한 기둥과 묶여 있다.

## 단계별 계획 (위험·의존도 순)

| 단계 | 내용 | 의존/위험 |
|---|---|---|
| **0. 토대** | 구글 로그인(`credentials` 테이블 google provider) · 저장 추상화 확정(SQLite↔Postgres) · always-on 서버 방향 결정 · **사용량 기록 스키마 자리 예약** | 나머지 전부의 바닥 |
| **1. 모델 다양화** | 무료 엔드포인트 중개(NVIDIA build / OpenRouter `:free`) · BYOK | 위험 낮음, 즉시 가치. provider 추상화 확장 |
| **2. 앱급 권한(웹분)** | 세션 허용 · 권한 건너뛰기 · 키 관리 UI · 모델 선택 | "클라이언트화"의 핵심 |
| **3. 멀티모달·깊이** | 이미지 보기(Claude base64 + Codex `-i`) · 세션 메모리(2-a) · 거주자 핑퐁 | 1·2와 병행 가능 |
| **4. 네이티브 앱** | file access · voice · 기기 신원 · OS 권한 | 권한 기둥 나머지. 웹 천장 넘기 |
| **먼 미래. 유료 구독** | 결제·사용량 측정·마진·법무 | 사용자 붙은 뒤 |

배포 모드(기둥1)는 이 과정에서 자연히 따라온다.

## always-on 갈림길 (0단계에서 결정 필요)
구글 로그인 리다이렉트 URI가 고정 도메인을 원하므로, 먼저 정해야 함:
- **A. 내 PC 유지 + 터널 안정화** — workers.dev 고정 주소(이미 있음)를 리다이렉트 URI로. 작음.
- **B. 클라우드 control plane 분리** — 방·신원·채팅은 클라우드 always-on, 에이전트만 로컬 연결. 제대로지만 큰 공사.

## 즉시 잔불 (비전과 별개로 정리할 것)
- 세션 자동 갱신(슬라이딩 만료) — 게스트 "안 끊김" 경험. (현재: 만료 시 자동 재입장까지만 구현됨)
- **백엔드 견고화** — provider 입장 안정성(아래), 에러 처리, 동시성.
- R4 방별 로그 분리 / R5 App.tsx 훅 추출 / R3 잔여.

## provider 입장 안정성 — 조사 완료 (2026-06-15)

**관찰**: 터미널에서 CLI들에게 "방 가서 살아라"고 시키니 각자 다르게 망가짐.
- Codex: 호명될 때까지 수동(readonly처럼) — 사실 정상 동작
- Gemini CLI: 자작 백그라운드 폴러가 "뇌(LLM) 없는 깡통 코드"라 계속 멈춤
- Grok: 같은 메시지 14연발 도배 + 동작 상태(self_service mode 등) 메타 누수

**근본 원인 (로그로 확정)**: 정당한 에이전트 발화 경로는 `/api/live-agents/{id}/lobby`
(runner/MCP, `live_agent_endpoint=True`) 하나뿐이고, 여기엔 전달 봉투(반복/메타 금지)
+ 턴 CAS가 걸려 있다. **"예전 정상 Grok"이 바로 이 runner 경로였다.** 그런데 6/14 사고는
CLI에게 "방 가서 살아"라고 시켜 **자작으로 raw `/api/room/say`를 두들긴** 것 —
ungoverned 경로라 도배·메타가 그대로 샜다. 즉 **에이전트가 잘못된 접속 경로로 들어온 것**이
원인이지, 메시지 패턴 자체가 아니다.

**provider별 거주(resident) 가능성:**
- **Grok**: `grok_resident.py` / `grok_live_session` 검증됨(connect/probe/official/restart/stop).
  → 정상작동 = runner로 띄우기. 도배 막기 위한 별도 코드 불필요.
- **Gemini**: resident runner 없음 + Gemini CLI 2026-06-18 폐기(→ Antigravity `agy`, 그러나 agy는
  `--print` 기반 = 우리 영구 금지). **현재 제대로 된 거주 경로 없음.** 인정하고 보류.
- Codex/Kiro/Cursor/Hermes/Antigravity: 각 `*_resident.py` 존재(성숙도 차이).

**결정 — 접속 경로 거버넌스는 WS 전환에서 한 번에 푼다 (지금 HTTP에 자물쇠 안 단다):**
지금 raw say에 "agent 차단/도배 가드"를 박아도 WS 전환 때 버릴 코드다. WS 핸드셰이크가
입구를 하나로 모으면 자연히 해결된다. WS 설계에 박아둘 요구사항:
1. **핸드셰이크에서 신원 + 클라이언트 종류(사람/runner/외부AI) 확정** — 입구가 하나로 통일
2. **에이전트는 거주 경로로만 발화** — 자작 폴링 루프 자체가 불가능
3. **연결당 상태로 도배/과속 관리** — stateless HTTP에선 어려웠던 것

→ 이 거버넌스는 **전송 계층 추상화(`RoomTransport`) + WS 구현**의 일부.
그때까지 Grok/Gemini 도배는 "runner로 띄우면 정상, 자작 raw say는 알려진 한계"로 둔다.
